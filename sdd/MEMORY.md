## 1. Principios destilados (aprendizajes transversales)

| # | Lección | Origen | Regla derivada |
|---|---|---|---|
| L0 | El reto NO se gana con tecnología sofisticada, sino con conexiones pertinentes, trazables y demostrables. | Lectura de las bases | Priorizar end-to-end funcional sobre features vistosas. |
| L1 | El dataset es pequeño (~2.000 entidades): todo cabe en memoria. | Auditoría de datos | Prohibido vector DB cloud / GPU / microservicios. Sería sobre-ingeniería. |
| L2 | El dataset mezcla español e inglés a propósito ("deserción" ↔ "student attrition"). | Análisis de documentos | Embeddings multilingües obligatorios; nunca TF-IDF solo. |
| L3 | "Similarity ≠ Relevance" es el examen central. | Documento Técnico | El score se descompone en features auditables, no en coseno. |
| L4 | Lo que no corre en vivo se considera "trabajo futuro". | Rúbrica | El sistema debe responder a consultas nuevas sin precargados. |
| L5 | Los NEED no traen método (el MD lo declara a propósito); el Jaccard simétrico de `compat_metodo` degenera a 0 en todo par NEED→candidato y volvía inalcanzable `antecedente_metodologico`. | Auditoría del dataset (Sprint-01.5) | Feature con un lado estructuralmente vacío: puntuar por **transferabilidad** (tipo-de-problema inferido → método real del candidato) y, sin señal, marcar **N/A + re-normalizar** — nunca un 0 falso. |
| L6 | Una feature "casi-constante" (siempre `False`, siempre 0, o auto-saturada en 1.0) no rompe ningún test escrito con fixtures a mano — sólo se ve midiendo la distribución sobre datos reales. Pasó 3 veces (`compat_metodo` en Sprint-01.5, `graph_linked`/`has_capability_support`/`compat_dominio`/`densidad_evidencia` en Sprint-03). | Auditorías repetidas antes de cada plan de sprint | Todo sprint que toque features debe correr (o extender) `test_feature_discrimination.py` sobre una muestra real antes de darse por cerrado — no basta con que los tests con fixtures pasen. |
| L7 | Implementar correctamente la LÓGICA de una feature relacional (`graph_linked`) no basta si el pipeline nunca le da la oportunidad de activarse — hacía falta EXPANDIR el pool de candidatos por el grafo, no solo puntuar lo que la búsqueda textual trajo. El síntoma (0 investigadores enlazados) sólo apareció corriendo el pipeline COMPLETO end-to-end, nunca en tests unitarios de la feature aislada. | Prueba manual del pipeline completo (Sprint-04) | Una feature relacional necesita que su fuente de candidatos también sea relacional, no sólo textual — probar la pieza aislada no sustituye probar el recorrido completo con datos reales. |
| L8 | Un test que compara strings en memoria no prueba que ese string sea seguro de IMPRIMIR — `TemplateExplainer` usaba "→" (Unicode) y pasaba todos sus tests, pero reventaba con `UnicodeEncodeError` al redirigir la salida del CLI en Windows (`cp1252` por defecto). | Ejecución manual de la demo, no de los tests (Sprint-05) | Para cualquier texto que vaya a stdout/un archivo/un log, preferir ASCII plano en vez de Unicode decorativo, o probar explícitamente la escritura a un stream con encoding restringido — no basta con `assert texto == esperado`. |
| L9 | Los tests con `TestClient` que sólo golpean `/api/*` (JSON) no cazan bugs de las rutas HTML (firma de `TemplateResponse`, selección de nodos del mini-grafo) — un test verde en JSON no prueba que la página se renderice. | Recorrido manual con curl de las 5 páginas HTML tras escribirlas (Sprint-06) | Cuando existen dos superficies para el mismo dato (JSON y HTML), cada una necesita su propio ejercicio real — aunque compartan el mismo DTO de `presenters.py`, la capa de renderizado (Jinja, selección de qué mostrar) es código nuevo que los tests del otro formato no cubren. |

| **🐛 `TemplateResponse` cambió de firma en la versión instalada de Starlette** | `templates.TemplateResponse("name.html", context)` (la firma "vieja", todavía documentada en muchos tutoriales) hace que Starlette interprete el string como `request` y el dict `context` como `name` — `TypeError: cannot use 'tuple' as a dict key` al intentar cachear la plantilla, porque el "nombre" termina siendo un dict. La firma instalada exige `(request, name, context)`. Se cazó recorriendo manualmente las 5 páginas con curl, no con los tests (los tests usan `TestClient` pero no aserían sobre contenido HTML de todas las rutas). Lección: cuando una librería expone una firma con múltiples parámetros del mismo tipo posicional (dos strings), un cambio de versión que reordena argumentos falla en runtime, no en import — hace falta ejercitar cada ruta HTML al menos una vez, no sólo el JSON. |
| **🐛 Mini-grafo centrado en la query casi nunca mostraba aristas explícitas** | El primer diseño de `subgraph_svg` centraba el grafo en la entidad de la CONSULTA y tomaba como nodos el top-14 global por rank — pero los resultados mejor rankeados para un NEED son casi todos PROJECT/THESIS/NEED, que no son vecinos de grafo entre sí (las aristas reales conectan PROJECT↔RESEARCHER, THESIS↔RESEARCHER, no PROJECT↔PROJECT). Resultado: casi siempre 0 aristas sólidas, sólo punteadas — visualmente sugería "no hay estructura real" cuando sí la hay. Encontrado probando manualmente `/connection/{id}` con el modelo real, no en los tests unitarios de `presenters.py` (que sólo prueban invariantes numéricos, no la selección de nodos). Fix: centrar el grafo en la entidad EN VISTA (no la consulta) y tomar como nodos sus vecinos REALES de `graph.neighbors()` primero; la consulta entra como un nodo aparte con arista punteada ("así se llegó aquí"). Mismo principio que ADR-011 aplicado a la UI: la estructura real hay que ir a buscarla explícitamente, no asumir que cae dentro del top-N por score. |
| **🐛 `faiss` + `torch` no coexisten en el mismo proceso en macOS** | Al instalar `sentence-transformers` (torch) junto a `faiss-cpu` para correr los tests `@slow` reales, el proceso abortaba con `SIGABRT` ("OMP: Error #15") la primera vez que se importaban ambos — cada librería trae su propio runtime OpenMP y el segundo registro aborta. No es un defecto de este código; es un conflicto conocido entre esas dos librerías nativas en macOS. Fix: `os.environ.setdefault("KMP_DUPLICATE_LIB_OK", "TRUE")` al inicio de `dense_index.py` y `sentence_transformer_provider.py` (antes de sus imports pesados) — inocuo aquí porque ninguna de las dos usa paralelismo OpenMP dentro de la otra. Mismo patrón que la nota de infraestructura de Sprint-03 (venv en ruta corta para el `MAX_PATH` de Windows): un workaround de entorno documentado, no una corrección de lógica. |
| **✅ Regla A2 extendida sin romperla** | `interface/composition.py` es ahora el ÚNICO lugar (junto con `scripts/query_cli.py`, que lo reusa) autorizado a instanciar adapters concretos — las rutas de `api/routes.py`/`ui/routes.py` reciben el `QueryService` ya construido vía `Depends(get_query_service)`, nunca lo arman. Verificado en los tests de interfaz: `app.dependency_overrides` inyecta un `QueryService` con `HashingProvider` (offline) SIN disparar el `lifespan` real de `app.py` — se confirmó midiendo tiempo de ejecución (los 8 tests de `test_api.py` corren en ~2s, no en los ~15-20s que tomaría cargar el modelo real). |
| **✅ Regla A3 verificada hasta el HTML, no sólo hasta el dato** | Antes de este sprint, A3 ("todo resultado conserva su provenance hasta la UI") no tenía ninguna UI que verificar — sólo se probaba a nivel de datos (`test_ingestion.py`). `tests/interface/test_trazabilidad_ui.py` cierra el hueco: confirma que `source_file`/`field_name`/`entity_id` aparecen literalmente en el HTML renderizado de `/connection/{id}`, no sólo en el DTO. |
| **❌ Errores a evitar** | No usar `with TestClient(app) as client:` en los tests de interfaz — eso dispara el `lifespan` real (`QueryService.build(fast=False)`, que carga el modelo real) incluso con `dependency_overrides` puesto, porque el lifespan corre igual y sólo el resultado se ignora. Sin `with`, el lifespan simplemente no corre y el override basta. |
| **🔁 Acción para el próximo Sprint** | Sprint-07 (Evidencia de desempeño) necesita un mini-set de validación etiquetado para P@5/P@10 — la pantalla "Métricas" del sidebar ya existe deshabilitada ("Sprint-07"), lista para activarse cuando existan los números reales. No fabricar esa pantalla antes de tener datos, como ya se hizo con M8 en este sprint. |

## 3. Antipatrones detectados (lista negra)

| Antipatrón | Por qué es peligroso |
|---|---|
| Rankear por coseno pelado | Cae en todas las trampas del reto; el jurado lo desarma en la auditoría. |
| Grafo "bonito pero hueco" | Visual impactante sin scoring defendible = puntaje bajo en pertinencia. |
| Depender de la API del LLM para la lógica | Si cae la red en la demo, se cae el sistema. Usar adapter de plantillas como respaldo. |
| Devolver muchos resultados | "Más resultados ≠ mejor solución". Priorizar y podar. |
| Dejar la trazabilidad para el final | Si no se captura en la ingesta, no se reconstruye. |
